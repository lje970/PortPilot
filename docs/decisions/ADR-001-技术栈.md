## 1. 背景与决策要求

- 规划书 §5.1 将技术栈列为待定(D1),要求"全面调查后定案":四档候选(A Tauri2+Rust / B Qt6(C++·PySide6)/ C Electron+TS / D C#/WPF)各建最小工程,以**统一验收清单**实测对比。
- 平台决策(已定):Windows 优先,架构不锁平台。
- 本项目的第一技术红线:**高吞吐稳定性**(460800 满速持续流零丢包为 P0 验收线,921600 为 P1 探索评估,≥3M 不做 —— 2026-11-01 范围决策,规划书 §4.4 v1.2)。选型以此为一票否决项。

## 2. 测试环境与链路基线

- 环境:Windows 11 x64(本工作区机器),2026-11-01。
- 链路:Eltima 虚拟串口对 COM1↔COM2(用户环境现成);CH340(COM12)真实硬件当日被其他程序占用,列 M1 复验(G2)。
- 链路基线(`bench/results/matrix_*_link-baseline.md`):全波特率档零丢包零错块,吞吐上限 ~10.7 Mbps(与标称波特率无关)→ **被测 POC 收发差值可干净归因于各栈自身管线**。
- 场景:bench 纯发生器(COM2 灌流,30s,256B 序号块)→ 虚拟对 → POC(COM1 收),实际入流 9.3~10.6 Mbps;四栈同口径(探针协议 v1,RSS/CPU 由跑台 psutil 统一外部采样)。

### 过程发现(工程知识,均为一手实测)

1. **QSerialPort readyRead 在 ~10Mbps 持续流下丢数据 1.55%**;加 2ms 轮询抽干后 0.17% —— 印证调研"Qt 高吞吐必须配缓冲设计"(调研报告 §6.1)。
2. **System.IO.Ports 丢包 12.3%**,经 ArrayPool 消除分配 + 256KB 驱动缓冲两轮缓解后仍 8.8% —— 与调研"Windows 最稳"的一般印象相反,持续高流量是它的结构性盲区(ReadFile 同步路径 + GC/调度停顿 > 驱动缓冲窗口)。对本项目是**一票否决级**发现。
3. **Electron 管线在 IPC 批处理正确时扛得住**(0.097%),但 430MB 内存坐实调研结论;且 node-serialport 维护乏力(bus factor 低,一年一版)。
4. **Rust 核心零丢包、亚毫秒延迟、14MB 内存、527KB 单文件**;serialport crate 4.10.1 在 windows-gnu 工具链下编译顺利。
5. 收尾在途残余:POC 排水窗口统一 +5s 后各栈 ≤0.2%(负值=吸收上轮链路缓冲残留),对四栈公平。

## 4. 评分矩阵(1-5 分;实测项用数据,生态项用调研)

| 维度 | 权重 | A Tauri2+Rust | B PySide6 | C Electron | D WPF |
|---|---|---|---|---|---|
| 吞吐稳定性(实测) | ×3 | 5 | 4.5 | 4.5 | 2 |
| 内存/体积(实测) | ×2 | 5 | 3.5 | 1.5 | 3 |
| 现代 UI 开发效率 | ×2 | 4 | 3.5 | 5 | 3 |
| 跨平台预留(架构成本) | ×2 | 5 | 4 | 5 | 1 |
| 绘图/表格/日志组件生态 | ×1.5 | 4 | 4.5 | 5 | 3 |
| 依赖维护风险 | ×1.5 | 4(serialport crate 活跃) | 4(pyserial 冻结但稳;PySide6 官方) | 2(node-serialport 慢) | 3.5 |
| 学习曲线/团队上手 | ×1 | 2.5 | 4.5 | 4 | 4 |
| **加权总分(满分 65)** | | **57.5** | **52.75** | **51.0** | **33.75** |

> 计算示例(A):5×3 + 5×2 + 4×2 + 5×2 + 4×1.5 + 4×1.5 + 2.5×1 = 57.5。结论:**A > B > C > D**,A 领先 B 4.75 分,领先幅度主要来自吞吐稳定性(×3 权重)与内存体积(×2 权重)两个实测硬指标。

## 5. 决策

**采用组合 A:Tauri 2 + Rust(serialport crate)+ Web 前端(vanilla TS/React 均可,渲染层统一 33ms 节流)。**

理由(按重要性):
1. **唯一在"吞吐稳定性"上拿满分且零缓解的栈**,而这是产品第一卖点(SSCOM 式口碑的现代化替代);
2. 内存/体积数据(A 14MB/527KB vs C 430MB/318MB)对"现代化、便携、随身 U 盘工具"的定位是代差级优势;
3. 跨平台预留成本最低(Rust 核心层天生跨平台,GUI 层换壳即可),符合"Windows 首发、架构不锁平台"决策;
4. 评分矩阵领先,且与调研报告 §6.3 的"首选推荐"互相印证——**调研与实测两条独立路径收敛于同一结论**。

同时记录的次级默认(非本 ADR 正式决策,见 D3/D5 台账):脚本引擎倾向 Lua(mlua);插件机制 P1 设计。

### G1 执行记录(2026-11-01,一手踩坑,产品化直接复用)

1. **Git Bash 的 `usr/bin/link.exe` 遮蔽 MSVC 链接器**,且 rustc 的 MSVC 自动探测在本机失效 → 解决:`src-tauri/.cargo/config.toml` 显式指定 link.exe 全路径 + vcvars64 会话内编译(PowerShell/cmd,避免 MSYS PATH 污染);
2. **Tauri 2 ACL 权限**:前端 `listen()` 默认被拒(`plugin:event|listen not allowed by ACL`)→ 必须声明 `capabilities/default.json`(core:event:allow-listen 等)——产品必踩坑,已沉淀模板;
3. **WebView emit 路径的堆分配竞争**:事件 IPC 开启时读线程被堆锁竞争拖住 → 虚拟对缓冲小,瞬时饿死即丢包(5.6%);`TAURI_NO_EMIT` 对照实验证实纯管线零丢包。**产品化对策:I/O 线程免分配环形缓冲 + 提高线程优先级 + 上游批量事件**(已列入 M1 架构任务);
4. 内存口径:树合计 RSS-sum 对多进程 UI 会重复计入 WebView2 共享内存(~347MB/6 进程),核心进程真实 RSS **29MB**(对比:rust-core console 14MB);与 Electron 同口径对比 402 vs 430MB 仍略优,但 Tauri 的真实优势要用"核心进程/私有内存"口径呈现。

## 7. 备选预案(回退路径)

- 若 G1 失败(Tauri GUI 在本环境/团队环境不可行)→ **回退 B(PySide6)**:实测可达标(缓解后 0.17%),接受打包与杀软误报的处置成本;Rust 核心可保留为可选加速模块(pybind 替代为 PyO3 反向不适用,届时以 QSerialPort+轮询兜底架构为准)。
- C/D 不设回退路径:D 被实测一票否决;C 被定位否决(内存/体积)。
